## 一、 项目概述与重构目标

### 1.1 当前痛点
当前版本（v1.x）功能运转正常，但存在以下核心体验问题：
*   **UI 风格陈旧**：呈现“传统工具窗口”特征，缺乏商业软件的视觉质感。
*   **信息层级混乱**：文件列表、参数设置和操作区域边界模糊，缺乏留白与卡片化区分。
*   **缺乏数据感知**：首页及操作过程中缺少关键数据看板，用户无法直观感知工作效率。
*   **多主题缺失**：未支持 Windows 原生的 Light/Dark 主题跟随。

### 1.2 重构战略目标
将 FormatMaster 重新定位为**“全能格式处理平台”**，对标 Windows 11 原生应用及万兴科技、Adobe Express 等商业级软件。
*   **设计语言**：全面拥抱 Windows 11 Fluent Design System。
*   **架构范式**：引入 Modern SaaS Dashboard（现代看板）与 Card Based Design（卡片式设计）。
*   **视觉体验**：增加 Mica（云母）/ Acrylic（亚克力）毛玻璃效果，提供平滑动效与双主题切换。
*   **技术底线**：**严禁**使用 Electron、Web 套壳或更换 GUI 框架；**必须**基于现有 Python + PySide6 + PySide6-Fluent-Widgets 技术栈进行纯原生重构。

## 二、 全局设计规范 (Design System)

### 2.1 视觉风格关键词
`Modern` · `Clean` · `Professional` · `Fluent` · `SaaS` · `Windows 11` · `Card UI`

### 2.2 颜色与背景 (Color & Theme)
*   **全局背景**（内容区）：
    *   Light 模式：`#F5F7FB` (极浅灰蓝色，衬托白色卡片)
    *   Dark 模式：`#202020` (标准深色背景)
*   **窗口特效**：必须启用 `MicaWindow` 或 `AcrylicWindow` 半透明背景，带有 **圆角窗口 (Rounded Window)** 和 **窗口阴影**。
*   **主题切换**：必须支持系统级主题跟随、强制 Light、强制 Dark 三种模式。
*   **核心颜色**：
    *   主按钮/进度（Action）：`#00B4D8` (青蓝色)
    *   成功状态：`#52C41A` (翠绿，搭配淡绿底色)
    *   等待状态：`#FAAD14` (橙黄，搭配淡橙底色)
    *   失败状态：`#FF4D4F` (醒目红)

### 2.3 字体 (Typography)
*   **英文字体**：`Segoe UI Variable` 或 `Segoe UI`。
*   **中文字体**：`Microsoft YaHei UI`。
*   **字号标准**：
    *   主标题 (Title)：`20px - 24px` (Bold)
    *   数据看板数字：`24px - 32px` (Bold)
    *   正文/列表文本 (Body)：`14px`
    *   辅助信息/标签 (Caption)：`12px`

### 2.4 全局 UI 组件规范 (Components)
*   **卡片 (Card)**：使用 `qfluentwidgets` 的 `CardWidget` 或 `SettingCard`。圆角 `12px - 16px`，带有轻微内阴影或外阴影 (Soft Shadow)。
*   **按钮**：统一使用 `PrimaryPushButton`（主色按钮）、`PushButton`（标准按钮）、`TransparentPushButton`（透明背景图标按钮）。
*   **弹窗与通知**：必须使用 `MessageBox` 和 `InfoBar` 替代原生 QMessageBox，统一 UI 风格。
*   **图标**：**严格统一**使用 `FluentIcon` 库内所有图标，禁止随意引入第三方杂牌 PNG 图片。
*   **列表**：**严重警告：严禁使用 `QTableWidget`！** 须将文件行封装为自定义的 `QWidget` (CustomCardList)，并通过 `QListWidget` 的 `setItemWidget` 实现。

## 三、 全局窗口布局架构

采用经典的 **三栏结构**（左右分栏+顶部标题），摒弃旧版直接铺满的布局：

```
┌─────────────────────────────────────────────────────┐
│            顶部标题栏 (Custom Title Bar)             │  ← 50-60px
├─────────┬───────────────────────────────────────────┤
│         │                                           │
│ 左侧导航 │             右侧内容主区域                │  ← 自适应 (使用 SmoothScrollArea)
│         │    [ 统计看板 (Dashboard) ]               │
│ 可折叠  │    [ 文件列表/工具卡片 (Content) ]         │
│ 折叠64px│    [ 参数配置面板 (Settings) ]             │
│ 展开220px│   [ 底部操作区 (Action Bar) ]            │
├─────────┴───────────────────────────────────────────┤
│             底部全局状态与日志 (Optional)            │
└─────────────────────────────────────────────────────┘
```
*布局组价要求：顶部标题栏需包含 Logo、应用名称、搜索框、主题切换入口、设置入口。右侧内容区域必须使用 `qfluentwidgets` 的 `SmoothScrollArea` 实现丝滑滚动。*

## 四、 左侧导航系统 (Navigation)

*   **组件选择**：使用 `qfluentwidgets` 的 `NavigationView` 或自行封装的 `NavigationInterface`。
*   **交互功能**：支持展开/折叠动画、Hover 高亮、当前激活项左侧“小蓝条”指示。
*   **导航结构清单**（严格按照以下类别进行分组，菜单内支持拖拽排序需求暂不纳入此版）：
    1.  **🏠 首页** (Dashboard 看板)
    2.  **🔄 转换中心**
        *   视频转换
        *   音频转换
        *   图片转换
        *   文档转换
    3.  **✂️ 媒体工具**
        *   视频压缩 / 视频转 GIF / 提取音频 / 缩略图墙 / 视频下载 / M3U8下载
    4.  **📄 PDF工具**
        *   合并 / 拆分 / 提取 / 加密 / 解密 / 压缩 / 转图片
    5.  **🖼️ 图片工具**
        *   图片压缩 / 水印添加 / 预设裁剪 / OCR识别 / 二维码生成
    6.  **📂 文件工具**
        *   批量重命名 / 格式检测 / 哈希计算 (MD5, SHA1, 256, 512)
    7.  **📋 任务中心**
        *   当前任务 / 历史记录 / 失败重试
    8.  **⚙️ 设置中心**
        *   基础、性能、外观 (主题/动画)、更新、关于

## 五、 核心功能页面详细 UI 需求

### 5.1 首页 Dashboard (现代数据看板)
首页不仅是入口，更是用户感知能力的中心。
*   **顶部欢迎语**：“欢迎使用 FormatMaster，今天已经处理 XXX 个文件。”
*   **数据统计卡片区**（4 个独立的 CardWidget，带图二风格的**渐变底色**和**动画数字**）：
    *   **总处理文件**：数值 `5200` (累计)
    *   **节省空间**：数值 `36 GB`
    *   **当前任务**：数值 `3` (待处理/处理中)
    *   **运行状态**：文本 `正常` / `忙` (带状态点)
*   **快捷入口区**：使用 Grid 排列的卡片式快捷入口，点击后直接跳转相应模块（如：`视频转换`、`PDF工具`、`OCR识别` 等）。

### 5.2 视频/音频/文档转换页面（核心工作流）
此页面的设计是衡量是否达到“商业级”的关键。
布局顺序从上到下必须严格遵循：
1.  **文件上传区**：大面积的 `CardWidget` 面板，支持点击文件选择及**文件拖拽**（Drag & Drop）。
2.  **自定义文件列表区**：
    *   **列表行构成**：[缩略图] | [文件名] | [转换方向(MP4→MKV)] | [进度条/状态徽章] | [操作按钮(播放、删除等)]
    *   **状态徽章色彩语义**：
        *   成功：绿色 `#52C41A` 背景
        *   转换中：蓝色 `#00B4D8` 进度条
        *   等待中：黄色 `#FAAD14` 背景
        *   失败：红色 `#FF4D4F` 背景
3.  **参数设置区**：分为“基础参数”与“高级参数”（可折叠），使用平铺的下拉框与滑动条，每个控件需配有动态提示（ToolTip）。
4.  **底部操作与总进度区**：
    *   左：输出目录下拉框 + 文件夹选择图标。
    *   中：主按钮 `开始转换` (PrimaryPushButton，青色主题)，副按钮 `取消`。
    *   下：全局总进度条（Smooth 平滑进度）。
    *   右：**商业化激活窗**：`✨ 开通 PRO 享批量转换/硬件加速` 提频入口。

### 5.3 图片专项工具（预览+参数模式）
*   **布局**：采用 **左侧图片预览区**，**右侧参数配置区** 的双栏布局，而非上下列表。
*   **参数包含**：缩放比例、旋转角度、裁剪预设、灰阶、水印配置等。

### 5.4 任务中心与日志
*   **任务中心**：类似下载管理器的表格展示，展示文件名、类型、创建时间、速度、状态。**必须支持重试失败任务**。
*   **日志中心**：作为底部 Dock 栏存在。使用不同颜色标注日志级别（成功绿/错误红/警告黄/信息蓝），支持搜索、复制和导出日志文件。

## 六、 动画与微交互规范 (Micro-interaction)

商业软件的丝滑感来源于细节，开发过程中必须落实以下动画：
1.  **页面切换**：页面跳转时需伴随 `Fade` (渐隐渐现) 动画，而非生硬的闪烁刷新。
2.  **按钮反馈**：鼠标 Hover 到主按钮上时，需有阴影放大或背景渐变加深动画。
3.  **卡片悬浮**：卡片接收到鼠标 Hover 时，需有 `Elevation Animation` (向上浮起且阴影加深)。
4.  **列表增删**：当文件列表中新增或移除一个 Item 时，必须要有 Smooth Fade/Scale 的插拔过渡。
5.  **全局进度**：进度条数值变化需平滑过渡（不要 0%~100% 瞬间跳转）。

## 七、 开发落地执行方案

### 7.1 核心破局点建议
若要在 PySide6 + Fluent Widgets 中实现图二的效果，**必须跨越这 3 个门槛**：
1.  **放弃 QTableWidget，拥抱 QListWidget + 自定义 ItemWidget**：将每一个文件封装成一个独立的 `QWidget`，使用 `QHBoxLayout` 排放缩略图、文件名、状态组件、按钮组，再通过 `setItemWidget` 放入列表。只有这样做，才能实现漂亮的【状态徽章】和【操作按钮】。
2.  **多线程与信号解耦**：后台文件转换必须在 `QThread` 子线程执行，每处理一个文件或更新进度时，通过 `Signal` 向主线程发送数据，更新看板数字和文件列表状态。
3.  **全局配置持久化**：利用 `qconfig` 保存用户的主题设置、上次选择的分辨率、目标格式等，实现“记忆性”。

### 7.2 开发与验收流程要求
*   **分步走**：
    *   `Phase 1`（基建层）：搭建左右结构框架，引入 Mica 效果、主题切换，完成导航结构。
    *   `Phase 2`（组件层）：开发 `BaseCardWidget`（基础卡片）、`FileListItemWidget`（自定义列表项）、看板卡片。
    *   `Phase 3`（编排层）：将旧代码的逻辑（文件读取、FFmpeg 转换驱动）移植到新 UI 布局中。
    *   `Phase 4`（打磨层）：增加平滑动画、修复深浅主题下的文本颜色对比度（Dark 模式下段落文字需为纯白 `#FFFFFF` 或浅灰 `#E0E0E0`）。
*   **UI 验收标准**：重构后的界面，必须在视觉上与提供的【图二】参考图（Modern SaaS Dashboard）保持 95% 以上还原度。
