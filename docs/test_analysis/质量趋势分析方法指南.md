# 质量趋势分析方法指南

> 适用对象：测试团队 / QA 负责人
> 目标：把"散落的大量测试数据"变成"能看见质量走向、提前预警、支撑发布决策"的体系。
> 配套文件：《测试数据采集模板.xlsx》

---

## 一、为什么"数据很多但看不到趋势"

趋势看不出来，99% 不是数据量的问题，而是**数据形态**的问题。先对号入座：

| 数据形态问题 | 典型表现 | 后果 |
|---|---|---|
| 数据分散 | 用例在 TestRail、缺陷在 JIRA、汇总在 Excel | 无法关联，只能单看 |
| 口径不统一 | "通过率"有人算 715/800，有人算 715/760 | 数字对不上，无法对比 |
| 没有时间维度 | 只记当前状态，不记"哪一轮、哪一天" | 无法画时间序列，趋势无从谈起 |
| 没有基线 | 不知道"正常水平是多少" | 波动来了也判断不了是否异常 |
| 只存结果不存原因 | 失败用例没记失败分类/根因 | 知道坏了，不知道为什么坏 |

**第一步不是加更多指标，而是统一数据形态。** 用配套模板的 3 张表即可：

1. **用例执行记录**（每条用例每一轮的执行结果 + 失败原因分类）
2. **缺陷记录**（每个缺陷全生命周期 + 根因 + 是否逃逸）
3. **版本汇总**（每个版本的执行/缺陷/自动化汇总快照）

> 已有历史数据时，不必强求逐条回填——**优先回填"版本汇总"表**（10 分钟/版本），它能立刻画出 6 条关键趋势；用例和缺陷明细再逐步补齐。

## 二、指标体系：先定 6 个核心指标

指标贵精不贵多。以下 6 个覆盖"质量现状、趋势、预警、发布"四个场景，全部可用模板字段直接算出：

| # | 指标 | 公式 | 回答什么问题 |
|---|---|---|---|
| 1 | 用例通过率 | 通过数 ÷ 执行数 | 当前质量水平 |
| 2 | 缺陷逃逸率 | 线上缺陷 ÷ (测试期+线上缺陷) | 测试拦截能力（越低越好） |
| 3 | 新增缺陷收敛趋势 | 每轮/每版本新增缺陷数 | 质量在变好还是变差（**核心**） |
| 4 | 未关闭缺陷存量 | 开放缺陷数随时间 | 发布风险与质量债 |
| 5 | 平均修复时长 | Σ修复耗时 ÷ 关闭数 | 缺陷处理效率 |
| 6 | 用例有效率 | 发现过缺陷的用例 ÷ 总用例 | 用例资产价值 |

辅助指标（按需）：执行率、自动化覆盖率、回归失败率、缺陷密度、模块缺陷占比。

## 三、趋势分析方法：从数据到判断

### 1. 时间序列图（趋势的骨架）
- X 轴：**按轮次或版本号**（不是日期！同一版本多轮测试必须用"v2.3.0-R1/R2/R3"，否则收敛曲线会被抹平）。
- 三条必画曲线：
  - 新增缺陷数（每轮）——**应单调下降**，下降不明显 = 版本质量未收敛
  - 已修复缺陷数（每轮）——应追平或超过新增
  - 未关闭缺陷存量——应走"上升→峰值→下降"曲线
- 判读口诀：**新增下降 + 存量下降 = 质量向好；新增持平 + 存量上升 = 质量恶化。**

### 2. 移动平均（去掉噪声看真实走向）
- 用 3~5 期的移动平均替代原始点，避免单轮波动（比如某轮环境故障导致通过率跳水）误导判断。
- 计算示例（Python/pandas）：
  ```python
  df["通过率_MA3"] = df["通过率"].rolling(3).mean()
  ```

### 3. 基线对比（异常才被看见）
- 先取最近 3~5 个正常版本建立基线（如通过率均值 ± 1.5σ）。
- 新数据点超出基线区间 → 触发预警，去查原因（是环境问题、回归引入、还是用例问题）。
- 没有基线的团队，第一版基线就是"你手上最近 5 个版本的平均值"，先跑起来再校准。

### 4. 根因定位（帕累托 + 分层）
- 对失败用例和缺陷做**帕累托分析**：按"失败原因分类 / 模块 / 缺陷类型"分组合计，前 20% 的类别往往占 80% 的失败。
- 重点看三个维度的交叉：`模块 × 失败原因`（哪个模块的哪类问题最多）、`阶段 × 严重度`（哪个阶段放走了严重缺陷）、`根因 × 逃逸`（逃逸缺陷的根因是什么——这直接指向测试盲区）。

### 5. 缺陷逃逸专项
- 每个线上缺陷回填"根因"：是测试漏测（用例没覆盖）？还是需求/设计变更导致？还是环境差异？
- 逃逸率连续两个版本上升 = 测试资产与产品演进脱节，优先补用例而非加人。

## 四、发布就绪判定（门禁模型）

把"感觉差不多能发"变成可量化的门禁，**5 条全过才允许发布**：

| 门禁 | 通过标准 |
|---|---|
| 缺陷收敛 | 最近一轮新增缺陷 ≤ 1 且连续两轮下降 |
| 严重度清零 | 无"致命/严重"级开放缺陷 |
| 存量控制 | 未关闭缺陷 ≤ 基线值，且无高危 |
| 回归稳定 | 回归轮失败率 ≤ 1%，且非环境原因 |
| 逃逸受控 | 本版本逃逸率 ≤ 5%（或连续 2 版未超基线） |

任一门禁不满足 → 输出"有条件发布"清单（必须修复项 + 可接受风险项），供管理层决策，而不是拍脑袋。

## 五、质量看板体系（长期自动监控）

目标：每周自动产出，无需手工拼报告。建议 3 层：

1. **周报看板（常规）**：通过率、执行率、新增/关闭/存量缺陷、自动化覆盖率——周环比 + 移动平均 + 预警标红。
2. **版本报告（决策）**：该版本的收敛曲线、门禁 5 项结论、缺陷帕累托 Top3、逃逸率、发布建议（GO / 有条件 / NO-GO）。
3. **季度总结（改进）**：缺陷密度变化、用例有效率、测试投入 ROI、改进措施效果验证。

> 落地路径：先用 Excel 模板手工产出 2~3 期周报（验证指标口径）→ 把数据导入 pandas 脚本或 Power BI 自动化 → 接入 CI 测试报告自动回填。
